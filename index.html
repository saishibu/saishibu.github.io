Selected work

  • JMDT chain

    Layer 2 network with zk-rollups, DAG execution, AVC consensus and DID-based querying. I lead its architecture.

    Go, gRPC, zk-rollups, DID

  • AVC

    Asynchronous Validation Consensus for the JMDT chain. Votes converge through a CRDT instead of lockstep rounds, so a vote counts whenever it arrives. Each BLS vote is bound to block hash, chain ID and height, so it cannot be replayed onto another block, fork or network.

    Go, BLS aggregation, CRDT, quorum certificates

  • ThebeDB

    The JMDT node's state store, which I architected and built. Each append lands in a BadgerDB log and in PostgreSQL within one two-phase commit, so the queryable view never drifts from the canonical record. Signed checkpoints make the chain head tamper-evident.

    Go library, BadgerDB, PostgreSQL, two-phase commit, DuckDB CDC

  • Auspex

    Jupiter Meta's in-house zkVM, built on its own STARK modules. It proves JMDT transactions and blocks for rollup verification and Ethereum settlement, and serves proofs over gRPC.

    zkVM, STARKs, gRPC

  • JMDT tokenomics

    Economic model for the JMDT network, designed to stay sustainable as it grows.

    Token design

  • SuperJ

    Blockchain-backed engagement platform for consumers, shipped as a mobile web app and SDK.

    Smart contracts, mobile SDK

  • Hercules

    Research platform for data-backed decisions: AI-built surveys answered by verified respondents. My work brought its data on-chain with zero-knowledge proofs.

    Zero-knowledge proofs, on-chain data
